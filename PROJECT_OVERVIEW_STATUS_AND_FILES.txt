PART 1: PROJECT STATUS & CAPABILITIES SUMMARY
================================================================================

1. SYSTEM STATUS: FULLY OPERATIONAL & PRODUCTION READY
   - Backend API: Running on FastAPI (ASGI) and Uvicorn on http://0.0.0.0:8000
   - Vector Store: FAISS Index with 139 dense semantic vectors (384-dimensional)
   - Relational Database: SQLite (evorag.db) managed via SQLModel / SQLAlchemy ORM
   - Consensus LLM Engine: Dual-tier orchestration combining Google Gemini API
     (gemini-2.5-flash / gemini-1.5-flash) with local Ollama LLM execution
   - Frontend UI: ChatGPT-style responsive single-page web application (HTML5,
     Vanilla JavaScript, CSS3, Chart.js)

2. CORE FUNCTIONAL CAPABILITIES:
   a. Multi-Persona Consensus Synthesis:
      - 8 distinct analytical personas evaluate every query from different perspectives:
        1. analytical-critical (policy mechanisms, structural analysis)
        2. empirical-evidential (verified dates, metrics, data points)
        3. adversarial-skeptical (counter-arguments, stakeholder positions)
        4. synthesis-integrative (holistic themes, big picture)
        5. domain-expert (technical, legal, and subject depth)
        6. temporal-contextual (historical evolution and future trajectories)
        7. risk-evaluative (operational vulnerabilities, impact analysis)
        8. creative-lateral (cross-disciplinary and unconventional angles)
      - Computes an 8x8 peer-scoring evaluation matrix across factual grounding,
        reasoning quality, and completeness to elect winning perspectives.

   b. Multimodal Document & File Intelligence:
      - Supports direct drag-and-drop file uploads for PDF, DOCX, TXT, CSV,
        XLSX, PNG, JPG, and JPEG.
      - Automatically extracts tabular datasets, text paragraphs, and prepares
        base64 image payloads for multimodal vision grounding.

   c. Temporal News Event Tracking & Evolution:
      - Automatically clusters real-world news articles into evolving event entities.
      - Tracks event status progression (Emerging -> Developing -> Ongoing -> Resolved).
      - Computes chronological milestones, policy shifts, clarifications, and controversies.

   d. Personalized News Discovery & Dynamic Feeds:
      - Covers 18 major journalistic categories (AI, Technology, Cricket, Sports,
        Politics, Business, Economy, Agriculture, Science, Healthcare, etc.).
      - Decoupled user interest scoring adapts dynamically to reading habits without
        compromising underlying peer factual consensus.

   e. Rich Visual Responses (ChatGPT-Style Media & Charts):
      - Top Media Carousel: Queries article photos or matches high-resolution
        editorial imagery with publisher attribution chips.
      - Bottom Dynamic Visualizations: Mounts responsive Chart.js components
        (Multi-Persona Consensus Radar Charts, metric Bar Charts, Line Charts,
        and chronological Timelines).

   f. Deterministic Response Sanitation:
      - Enforces clean, authoritative journalistic prose.
      - Completely strips internal pipeline jargon (e.g., "Emerging with 85% confidence",
        "single recorded chronological data point", "assessed confidence rating").
      - Completely eliminates robotic meta-academic disclaimers ("Logical Structure
        and Assumptions", "Analytical Critique and Limitations", "Implications and Risks").
      - Only flags knowledge gaps when the user explicitly requests future predictions.

   g. Sub-Minute Latency Performance:
      - Async FastAPI endpoints with bounded timeouts.
      - Pre-warmed FAISS memory caching and thread-pool retrieval.
      - Fast structured consensus routing to eliminate multi-round query bottlenecks.

PART 3: WHAT EACH FILE DOES IN BRIEF & TOOLS USED
================================================================================

--------------------------------------------------------------------------------
1. api.py
--------------------------------------------------------------------------------
- Purpose in Brief:
  The central backend application entry point. Initializes FastAPI, configures
  CORS middleware, mounts static files for the frontend UI, registers all API
  routers (auth, news, events, conversations, personalization), and exposes the
  primary /query/consensus endpoint.
- Tools & Libraries Used:
  * fastapi (FastAPI, APIRouter, Request, HTTPException): High-performance ASGI web framework.
  * uvicorn: Lightning-fast ASGI web server.
  * sqlmodel (Session, select): ORM for session dependencies and database queries.
  * pydantic (BaseModel): Strict request/response payload schema validation.
  * starlette.middleware.cors (CORSMiddleware): Cross-origin resource sharing security.
  * starlette.staticfiles (StaticFiles): Serves client HTML/CSS/JS frontend assets.

--------------------------------------------------------------------------------
2. pipeline.py
--------------------------------------------------------------------------------
- Purpose in Brief:
  The master orchestration pipeline for EvoRAG. Coordinates Step 1 (Input
  Understanding), Step 2 (Intelligent FAISS Retrieval & Temporal Context Lookup),
  Step 3 (Multimodal Consensus via Gemini Structured Generation), and Step 4
  (Local Multi-Persona Racing & Voting). It includes deterministic cleaning of
  the final answer and invokes response planning for media and charts.
- Tools & Libraries Used:
  * asyncio: Async concurrency for running retrieval, understanding, and consensus.
  * re (Regular Expressions): Powers clean_final_answer to strip internal telemetry,
    confidence ratings, and unwanted robotic academic headers.
  * sqlmodel (Session): Database session access for user and event contexts.
  * pydantic: Structured component schemas and query validation.
  * logging: Production logging of pipeline timing and execution branches.

--------------------------------------------------------------------------------
3. retriever.py
--------------------------------------------------------------------------------
- Purpose in Brief:
  Performs hybrid dense retrieval against FAISS. Encodes queries into 384-d
  vectors, computes cosine similarities, scores freshness/relevance, evaluates
  evidence sufficiency, and performs temporal context lookup for evolving events.
- Tools & Libraries Used:
  * faiss-cpu (faiss): Ultra-fast vector similarity search library.
  * numpy: Dense vector array manipulation and normalization.
  * sentence-transformers: Converts natural language text into dense semantic embeddings.
  * sqlmodel (Session, select): Retrieves associated metadata and event records.
  * re (Regular Expressions): Keyword boundary matching for event candidate filtering.

--------------------------------------------------------------------------------
4. embedder.py
--------------------------------------------------------------------------------
- Purpose in Brief:
  Singleton wrapper for the sentence embedding model (`all-MiniLM-L6-v2`).
  Ensures the neural network is loaded into memory only once and provides thread-safe
  batch and single-query vector encoding.
- Tools & Libraries Used:
  * sentence-transformers (SentenceTransformer): Open-source Hugging Face embedding model.
  * torch (PyTorch): Deep learning runtime engine powering MiniLM on CPU.
  * numpy: Vector array normalization and dimension validation.

--------------------------------------------------------------------------------
5. gemini_client.py
--------------------------------------------------------------------------------
- Purpose in Brief:
  High-speed HTTP client for the Google Gemini API. Handles structured multimodal
  prompts (text, base64 images, document chunks, tables), manages model failover
  between gemini-2.5-flash, gemini-flash-lite, and gemini-flash, and handles
  Google Search Grounding when real-time external discovery is needed.
- Tools & Libraries Used:
  * httpx (AsyncClient): High-throughput async HTTP client with connection pooling.
  * os & dotenv: Secure loading of GEMINI_API_KEY from environment variables.
  * json: Serialization and parsing of structured JSON responses.

--------------------------------------------------------------------------------
6. file_processor.py
--------------------------------------------------------------------------------
- Purpose in Brief:
  Multimodal file processing engine for uploaded files. Extracts clean text,
  tabular summaries, and visual data from PDFs, Word documents, plain text,
  spreadsheets, and images, enforcing strict size limits (25MB per file, 60MB total).
- Tools & Libraries Used:
  * pypdf / pdfplumber: Extracts text and tables from PDF documents.
  * python-docx (docx): Extracts headings, body paragraphs, and tables from Word (.docx).
  * openpyxl & pandas: Parses Excel (.xlsx) and CSV spreadsheets into structured tables.
  * PIL (Pillow): Image loading, resizing, validation, and format conversion.
  * pytesseract: Optical Character Recognition (OCR) for extracted image text.
  * base64 & hashlib: Base64 encoding for vision models and SHA-256 duplicate hashing.
